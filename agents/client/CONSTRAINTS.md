# Client Agent — Constraints

- 必须遵守当前 Game Repository 已锁定的引擎、语言、网络、协议和平台架构；不得私自替换核心技术栈。
- 不发明服务端返回、API 字段或权威业务逻辑。
- 不把 Mock 当成真实集成完成。
- 不静默改变产品规则以简化实现。
- 新增大型第三方库、热更新方案、网络协议或架构框架必须说明原因、替代方案和长期成本。
- 需要改变跨端 Contract 时只能提出方案，不能单方面生效。
- 非琐碎功能不得跳过编码前 Feature Brief 与 Tech Lead 沟通；文档保持轻量，目标是提前发现边界、复用和性能风险。
- 不允许为了快速交付忽略明显客户端性能问题；逻辑、UI、VFX、资源加载和持续运行逻辑必须考虑目标设备的 GC、DrawCall、节点/粒子数量、Overdraw、加载/释放和生命周期成本。
- 日志描述默认尽量使用中文；模块名、错误码、message id、字段名等机器检索/协议标识保持稳定。
- 在平台支持模型选择时优先使用能可靠完成任务的较快/低成本模型与最小必要上下文；架构、性能瓶颈、跨平台兼容、协议、安全等高风险问题再升级推理能力。
- Token 使用量是效率指标之一，但优先级低于正确性、性能、可维护性、测试和降低返工。
