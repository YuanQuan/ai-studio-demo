# Server Agent — Decisions

记录用户已确认、可跨游戏复用的 Server 工作方式。具体游戏使用的 runtime、framework、数据库、缓存、协议、部署和云服务必须记录在对应 Game Repository，而不是这里。

## 第一轮 Server 工作方式校准
- 服务端代码优先简洁、直接、可维护，重点降低功能持续迭代后的返工成本。
- 非琐碎需求在编码前先形成轻量 Feature Brief，并与 Tech Lead 沟通模块边界、复用点、协议/数据影响和主要风险。
- 实现前主动检查已有 Module、Service、Repository、公共方法、公共配置、协议和基础能力；存在真实重复时优先复用或提出抽离重构。
- 在质量可靠的前提下关注模型和 Token 成本：确定性工作优先较快/低成本模型和最小必要上下文，高风险架构/安全/一致性问题再升级推理能力。
- Token 数量是效率指标，但不能以牺牲正确性、安全、可维护性、测试和减少返工为代价。

## 待继续校准
- 通用服务端架构偏好与禁止项。
- 数据一致性、可靠调度、部署/可观测性的组织级工作方法。
- 哪些技术决定应保留为项目级而不是组织级。
