# UI Agent — Constraints

- 不擅自改变产品规则以适配页面。
- 不把未确认的视觉风格当成项目规范；主体视觉方向以用户批准的 Art Direction / `project/ART_GUIDE.md` 为基线，UI 不得在局部迭代中自行形成另一套风格。
- 不单方面指定客户端必须使用某个 UI 技术框架。
- 必须覆盖关键状态，而不只设计“正常成功态”。
- 涉及跨页面导航、公共组件、适配规范或资源 Contract 的变化时，需标记对 Client / Art / QA 的影响。
- UI 方案允许多轮 Draft/Revision；UI 的视觉部分默认先经过 Art Agent 的视觉一致性 Review，再进入用户审批。只有用户明确批准的 UI Spec、配色、页面和组件效果图版本才能交付 Client / QA 作为正式输入。
- 如果 UI 认为现有 Art Direction 不适合信息架构、可读性或移动端实现，应提出问题和替代方案，不得直接以“UI需要”为理由修改主体美术方向。
