# Escalation Rules

专业 Agent 在正式项目执行中遇到以下情况必须提交 Agent Request 给 Master，而不是自行拍板。用户与该 Agent 直接进行职责/能力校准时，不需要 Master 充当中间人；但若校准结论影响跨角色 Contract 或项目级决定，则按 `governance/capability_change_protocol.md` 升级。

## 必须升级
- 核心玩法语义不明确或相互冲突。
- 价格、付费、奖励、经济平衡发生实质变化。
- 需要破坏已有 API / 数据格式 / 存档兼容。
- 当前正式项目需要新增大型框架、第三方服务或显著基础设施成本。
- 角色能力偏好与当前项目正式技术选型发生冲突。
- 需要明显扩大美术、UI、VFX 或开发范围。
- 当前任务与 `project/DECISIONS.md` 冲突。
- 缺少权限、关键资产、密钥、环境或外部依赖导致无法验证。

## 可以自行处理但要记录
- 不改变需求语义的小型命名和代码组织决定。
- 可逆、低风险的实现细节。
- 测试用 Mock / Fixture，但必须明确不能作为正式交付冒充真实集成。

## Request 类型
- `CLARIFICATION`：需要澄清。
- `DEPENDENCY`：需要其他角色或外部输入。
- `CHANGE`：申请改变已批准范围或契约。
- `DECISION`：存在多个重要方向需要选择。
- `BLOCKER`：无法继续执行。

Request 必须说明：当前事实、为什么无法自行处理、建议选项、影响范围和推荐选择。
