## 1. 设计目标

建立一个原创、轻松、适合竖屏单手休闲体验的猫咪视觉体系。视觉必须服务核心玩法：玩家需要在短时间内辨认猫咪等级、判断真实占地、看清危险线和连续合成结果，而不是被复杂装饰干扰。

本方向选择“**柔软圆润的贴纸绘本感**”作为第一版主体语言：以简化猫咪轮廓、低细节面部、温暖奶油色空间、局部布艺/缝线装饰构成统一风格。它强调亲和、可读、原创和低资产复杂度，适合后续在 Cocos 中实现 2D Sprite、轻量骨骼/缩放动画和简单 VFX。

## 2. 核心视觉关键词

1. **圆润软萌**：主体由圆、椭圆、软三角耳等大形构成。
2. **贴纸感**：角色轮廓有明确外边界，便于从背景中分离，也帮助玩家感知碰撞占地。
3. **温暖奶油色**：场景偏柔和暖色，避免高饱和背景与猫咪争夺注意力。
4. **等级一眼可辨**：等级越高，体积、毛量、纹样层数、装饰特征逐步增强。
5. **轻量绘本**：保留少量手作感细节，但不使用复杂纹理或写实毛发。
6. **玩法优先**：视觉轮廓和碰撞轮廓接近，装饰不制造“虚假体积”。

### 禁止偏离项

- 不走写实猫咪摄影/毛发渲染风格。
- 不使用高频细碎花纹覆盖整个主体。
- 不通过超长尾巴、宽帽檐、大翅膀等装饰扩大视觉轮廓却不扩大碰撞体。
- 不复制任何现有合成游戏的角色造型、容器布局、UI 构图、图标、音效视觉化或独特美术表达。
- 不把场景做成复杂室内插画，避免危险线、落点和猫咪边缘难以阅读。

## 3. 设计思路与理由

### 3.1 为什么选择圆润贴纸感

核心玩法依赖物理堆叠。圆润主体天然适合稳定滚动和堆叠，同时也能减少视觉轮廓与近似圆/凸形碰撞体之间的误差。贴纸式描边让相互接触的猫咪仍能清楚分辨边界，尤其在连续合成和高堆叠密度下更重要。

### 3.2 为什么不做高度写实

写实猫咪的耳、腿、尾、毛发会产生大量视觉突出部位；如果碰撞体完全拟合，物理会不稳定且难调；如果碰撞体不拟合，玩家会感到“明明没碰到却发生碰撞”。MVP 更适合使用抽象、圆润、可读的大轮廓。

### 3.3 与移动端约束的关系

- 9:16 竖屏下，猫咪会在小尺寸状态下大量同时出现，因此面部必须只保留最关键的 2–4 个识别点。
- L1–L3 直接投放，必须特别容易区分，不能只靠尺寸差。
- 危险状态时视觉层级必须满足“危险线 > 猫咪 > 背景装饰”。
- HUD 使用少量大数字和简洁卡片，不做密集边框和重纹理。

## 5. 视觉体系

### 5.1 角色基础造型语言

统一骨架：
- 主体：接近圆形/短椭圆。
- 耳：两个小型软三角，耳尖不得成为远离主体的大突出。
- 尾：默认只以贴身弧形/短尾符号出现，不显著扩大碰撞感知边界。
- 眼睛：小圆/短弧，避免复杂高光。
- 嘴鼻：极简“点 + 小弧”。
- 外轮廓：概念上保持约主体直径 1.5%–2.5% 的视觉描边比例；实际像素由后续资产规范适配。

### 5.2 10 级视觉递进

这些名称只是设计标签，不是正式产品命名。

| 等级 | 视觉主题 | 主要区分特征 | 装饰预算 | 碰撞可读性规则 |
|---|---|---|---|---|
| L1 | 小团子幼猫 | 最小体积 + 单色脸 | 0–1 个小细节 | 近圆轮廓，无外挂装饰 |
| L2 | 耳尖幼猫 | 耳尖双色 + 更宽脸 | 1 | 耳尖仍贴近主体 |
| L3 | 条纹幼猫 | 额头三短纹 | 1–2 | 条纹只在主体内部 |
| L4 | 花斑猫 | 大块不规则面部色块 | 2 | 色块不改变外形 |
| L5 | 铃铛猫 | 小型颈圈/铃铛符号 | 2 | 铃铛位于轮廓内下缘 |
| L6 | 围巾猫 | 贴身短围巾图形 | 2–3 | 围巾不向侧面伸出 |
| L7 | 蓬松猫 | 外缘增加少量软毛瓣 | 3 | 毛瓣限制在碰撞轮廓容差内 |
| L8 | 大尾绒猫 | 背部/侧面短绒弧形纹 | 3–4 | 尾部作为内部图形处理 |
| L9 | 星月猫 | 额头星/月纹 + 更厚毛量 | 4 | 不使用外置皇冠/大饰品 |
| L10 | 云团大猫 | 最大圆润体积 + 多层柔和纹样 | 4–5 | 仍保持单一清晰大轮廓 |

递进原则：
- 每级至少有 **体积 + 纹样/特征** 两个维度之一发生明显变化。
- L1/L2/L3 必须在缩小到 HUD 的 Next 预告尺寸时仍可区分。
- L7–L10 即使更华丽，也不得靠尖刺、长毛束或悬空饰品制造碰撞误解。

### 5.3 色彩体系 v0.1

整体色彩策略是“背景低饱和、猫咪中等饱和、状态色高识别”。

概念基础色：
- 背景奶油：`#FFF3DE`
- 容器暖木：`#D9A66F`
- 深描边：`#5B4A42`
- HUD 奶白：`#FFF9EF`
- HUD 深字：`#4A3D38`
- 安全辅助蓝绿：`#85C9B8`
- 危险珊瑚红：`#F16F67`
- 合成高光黄：`#FFD66B`

猫咪等级不采用完整彩虹顺序，而采用“奶油、橘、灰蓝、三花、薄荷、莓粉、紫灰”等软色组，避免后续 VFX 与危险红冲突。

### 5.4 场景 / 棋盘语言

概念为“**猫咪游戏软垫盒**”：
- 主玩法容器像圆角软木/软垫收纳盒，而不是玻璃杯或与参考游戏高度相似的容器。
- 背景只保留抽象窗光、墙面小挂饰、柔和地板分区等低对比元素。
- 容器侧壁宽而稳定，内侧区域保持干净。
- 危险线使用“短虚线 + 小布签”语言，不使用激光、警戒带等过强工业视觉。

### 5.5 UI 视觉语言

- HUD 卡片采用圆角软贴纸/布签形态。
- 分数数字是界面第一优先级；Next 第二；暂停/设置第三。
- 不使用复杂金属框、强渐变宝石、拟物按钮。
- 交互状态通过轻微缩放、阴影、描边变化表达。
- UI Agent 可调整布局与组件状态，但应保留：圆角、大留白、浅底深字、低装饰密度。

### 5.6 VFX 视觉语言

- 合成：短促“软弹 + 星点/毛屑”感，颜色取结果猫咪主色 + 暖黄高光。
- 连锁：可增加节奏与数量，但粒子尺寸保持小，不遮挡邻近猫咪边缘。
- 危险：线条呼吸 + 轻微珊瑚红晕，不做全屏频闪。
- Game Over：局部失去饱和度或轻压暗，不使用强烈震屏作为默认表现。

## 7. 一致性规则

后续必须保持：
- 猫咪主体永远是第一视觉焦点。
- 等级区分优先依赖体积、内部纹样和贴身特征，不依赖大外挂。
- 背景的最高局部对比度不得长期高于危险线或猫咪描边。
- 危险红仅用于警告/失败语义，不成为普通装饰主色。
- 合成高光可以更亮，但持续时间短，不能长期遮挡物理状态。
- UI / VFX 新增视觉方向在进入用户审批前先由 Art 做一致性 Review。

允许变化：
- 单只猫的具体配色、眼睛形状、内部花纹。
- 背景小装饰内容。
- HUD 卡片具体尺寸和位置。
- VFX 粒子数量、节奏和性能降级档位。

需要重新进行 Art Direction Review 的情况：
- 改成写实/像素/3D/强赛博等整体风格。
- 猫咪外轮廓从圆润短体变成长体、四肢明显或大配饰体系。
- 场景容器视觉逻辑整体更换。
- UI 大量引入高饱和、复杂纹理或强拟物语言。
