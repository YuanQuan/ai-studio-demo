# Tech Lead 评审 v0.1 — 核心玩法

- 任务：`GAME-004-CORE-TECH-DESIGN`
- 被评审 Artifact：`TECH_DESIGN_v0.1.md`
- 结论：**PASS —— 可以进入用户审批**

## 评审摘要

本设计保持了已经批准的 Product 玩法语义，同时让 MVP 保持客户端本地、低复杂度实现。物理回调与领域决策被隔离；合成 Pair 选择采用稳定顺序，并能够防止源对象重复消费；分数与危险线逻辑基于模拟事件 / 模拟时间，而不是渲染帧率。

## 检查结果

| 检查项 | 结果 | 说明 |

## 评审动作

进入用户审批前没有阻塞项。

批准后进入实现阶段时必须执行：
1. Client 不得直接在物理 Contact Callback 中合成或销毁物理体。
2. 正式 QA 前，Client 必须实现 Tech Design 第 14 节要求的 Debug / QA 可观测能力。
3. 物理系数调优必须作为配置 / 原型校准工作，不得静默修改 Product 已批准数值。
4. 如果实际 Cocos Creator 项目版本 / API 与设计假设存在差异，只允许在 `PhysicsFacade` 内适配，不得改变领域 Contract。

## 风险说明

- 跨平台物理不保证逐比特确定性；QA 应验证规则语义和可控手感容差，不要求长时间模拟后的坐标完全一致。
- 最终 Collider 形状仍依赖获批 Art 轮廓；Tech Design 已让 `PhysicsFacade` 同时兼容圆形 / 简单凸形方案。
- 客户端本地 MVP 的结果不适合作为竞争性在线排行的可信成绩。未来如加入排行或付费奖励，必须新增权威性 / 安全设计。
