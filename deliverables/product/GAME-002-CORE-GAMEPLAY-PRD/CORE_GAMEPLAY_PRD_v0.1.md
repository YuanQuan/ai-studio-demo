## 1. 目标

把已批准 Product Outline 中的核心循环细化为可实现、可测试的产品规则：玩家在竖屏容器顶部控制待投放猫咪的水平位置，释放后由物理系统下落、碰撞、滚动和堆叠；相同等级猫咪接触后升级，产生分数并可能触发连续合成；当有效猫咪持续占据危险线以上区域达到 2 秒时结束本局。

本 PRD 的目标不是确定具体物理引擎、代码架构、UI布局或猫咪视觉，而是锁定玩家可感知的玩法语义和可验证行为。

## 2. 范围

### 2.1 本 PRD 包含
- 单局开始与核心运行态。
- 当前猫咪 / 下一只猫咪队列。
- 等级 1–3 的随机投放池。
- 水平瞄准、合法位置限制、释放和投放节流。
- 下落、碰撞、旋转、堆叠等玩家可感知物理行为目标。
- 1–10 级猫咪等级链。
- 同级合成、最高级处理、同时接触与连续合成语义。
- 本局合成计分。
- 危险线、2 秒连续容错、取消警告与 Game Over。
- 本局重置需要清理的核心状态。
- 可供后续 Tech / Client / QA 追溯的 Acceptance Criteria。

### 2.2 本 PRD 不包含
- 首页、暂停页、结算页的具体布局和交互视觉。
- 猫咪具体品种、名称、美术风格、表情和资产规格。
- 具体输入手势映射（拖动、点击、滑动等由 UI/交互阶段确定）；本 PRD 只定义“水平瞄准 + 释放”的语义。
- 具体 2D 物理引擎、碰撞库、固定时间步、代码结构或组件方案。
- 最佳分本地存储的技术实现。
- 微信/抖音 SDK 细节。
- 广告、付费、Meta养成、图鉴、货币、社交、多人、活动或服务端权威玩法。

## 3. 核心术语

- **等级 Level**：猫咪成长等级，MVP 为 `L1` 到 `L10`。
- **当前猫 Current**：玩家正在顶部控制横向位置、尚未释放的猫咪。
- **下一只 Next**：只用于预告，当前猫释放并满足下一次投放条件后成为新的 Current。
- **有效猫 Active Cat**：已释放进入物理棋盘、尚未被合成消费的猫咪。
- **合成 Merge**：两个同等级且均可消费的猫咪接触后，被原子消费并生成一个高一级猫咪。
- **危险线 Danger Line**：棋盘顶部附近的失败检测水平线；Current 在释放前不参与危险线检测。
- **危险计时 Danger Timer**：至少一个有效猫持续越过危险线时累计的连续时间。

## 4. 单局状态模型

核心玩法同时维护三组正交状态，避免“正在瞄准”和“正在危险警告”互相冲突。

### 4.1 Run State
- `RUNNING`：物理、投放、合成、计分、危险线都有效。
- `GAME_OVER`：本局结束，不再接受新的投放；最终分数固定。

### 4.2 Spawn State
- `AIMING`：存在一个 Current，可改变其水平瞄准位置并执行释放。
- `DROP_LOCKED`：上一只猫刚释放，新投放暂时锁定；棋盘继续模拟。

### 4.3 Danger State
- `SAFE`：没有有效猫持续满足越线条件，Danger Timer 为 0。
- `WARNING`：至少一个有效猫越线，Danger Timer 正在累计。

暂停/应用后台属于后续 UX / Platform 状态，但产品语义要求：暂停或进入后台时核心模拟与 Danger Timer 都不得继续推进。

## 5. 开局与随机队列

### 5.1 开局
新一局开始时：
1. `score = 0`。
2. 清空棋盘内所有有效猫与未完成合成事件。
3. `Danger Timer = 0`，Danger State = `SAFE`。
4. 独立随机生成 Current 和 Next。
5. Spawn State = `AIMING`，Run State = `RUNNING`。

### 5.2 投放池
MVP 仅允许 `L1 / L2 / L3` 直接进入随机投放池。

v0.1 基线概率：

| Level | Probability |
|---|---:|
| L1 | 33.33% |
| L2 | 33.33% |
| L3 | 33.34% |

规则：
- 允许连续出现相同等级，不设置保底、防连出或动态修正。
- L4–L10 只能通过合成得到，不能直接随机投放。
- 玩家必须始终能看到 Next 的等级/视觉预告；具体展示方式由 UI 阶段决定。
- 本 PRD 不要求玩家可见随机种子；后续 Tech/QA 可增加调试种子能力，但不得改变正式随机规则。

## 6. 水平瞄准与释放

### 6.1 瞄准语义
- Current 位于固定顶部投放高度，玩家只改变其水平坐标 `aimX`。
- `aimX` 必须被限制在棋盘左右边界内，使 Current 的有效碰撞体在释放瞬间不会穿出侧墙。
- Current 在释放前不参与棋盘碰撞、合成、危险线检测或计分。
- 玩家不能在本 PRD 中直接控制 Current 的垂直位置。

### 6.2 释放
玩家执行“释放”后：
1. Current 在当前 `aimX` 进入棋盘并成为 Active Cat。
2. 初始主动推力为 0；之后只受物理规则影响。
3. Spawn State 进入 `DROP_LOCKED`。
4. Next 被提升为待用的下一 Current；同时立即生成新的 Next，但在锁定解除前不可再次释放。

### 6.3 投放节流
为了避免玩家连续快速生成猫咪破坏空间判断，下一次投放必须同时满足：
- 上一只刚释放的猫已完全离开顶部“投放排除带”；以及
- 自上一只释放起至少经过 `0.25s`。

两项都满足后 Spawn State 回到 `AIMING`。

“投放排除带”的具体像素高度由 Tech Design 根据 Current 的最大可投放尺寸和顶部安全区确定，但行为必须保证新 Current 不会与上一只刚释放的猫在生成瞬间重叠。

## 7. 物理行为产品目标

本节只规定玩家可感知结果，不指定实现引擎。

- Active Cat 受向下重力影响，可发生平移和旋转。
- 猫咪之间以及猫咪与底部/侧壁之间发生实体碰撞，不能长期互相穿透。
- 堆叠结果允许轻微滚动、挤压式位置调整和连锁位移，但应能形成稳定堆叠。
- 整体手感为“低弹性、可滚动、较快稳定”，避免像高弹力球一样长期弹跳。
- 空棋盘中从标准投放高度释放 L1–L3 后，首次触底反弹高度目标不超过原下落距离的约 12%；此值是手感调优目标，不要求使用特定弹性系数实现。
- 猫咪可见主体轮廓与有效碰撞轮廓必须足够接近，避免明显“隔空碰撞”或大面积穿模；具体轮廓由后续 Art + Tech 联合约束。
- 帧率、平台或设备差异不得改变“同级可合成 / 异级不可合成 / 危险线连续2秒才失败”等规则语义。

## 8. 等级与尺寸基线

MVP 固定 10 级。正式视觉名称暂不在本 PRD 中决定，统一使用 L1–L10。

尺寸采用“棋盘可玩宽度百分比”作为 Product 初始调优基线；后续 Tech 将其映射到实际配置结构，Art 按可读轮廓制作视觉。

| Level | Baseline diameter / playable width | Direct spawn |
|---|---:|---|
| L1 | 9.0% | Yes |
| L2 | 10.5% | Yes |
| L3 | 12.5% | Yes |
| L4 | 14.5% | No |
| L5 | 17.0% | No |
| L6 | 19.5% | No |
| L7 | 22.5% | No |
| L8 | 26.0% | No |
| L9 | 30.0% | No |
| L10 | 35.0% | No |

这些数字用于建立第一版难度和空间占用基线；如果原型证明某一级造成明显卡死、过易或碰撞不可读，Product 必须记录调优结果。跨出本表整体设计意图的显著改动需要新版本审批。

## 9. 合成规则

### 9.1 基本规则
当两个 Active Cat 满足以下条件时可合成：
- 两者等级相同。
- 等级为 L1–L9。
- 两者均未在当前合成结算中被标记为“已消费”。
- 两者发生有效实体接触。

合成结果：
1. 两个源猫被原子消费，只能被消费一次。
2. 在两者接触位置附近生成一个 `Level + 1` 的新猫。
3. 新猫立即进入 Active Cat 集合并继续参与物理模拟。
4. 记录一次对应等级的合成得分。

### 9.2 最高级
- `L10 + L10` 不再升级。
- L10 之间仍正常发生物理碰撞和堆叠。
- L10 与任何等级接触都不会产生合成得分，除非它本身刚由 `L9 + L9` 生成；该次 `L9 + L9 -> L10` 正常计分。

### 9.3 同时接触与对象消费
- 同一个源猫在一次合成结算步骤中最多参与一次合成，禁止一只猫同时被两个合成事件消费。
- 三个同级猫同时接触时，只允许其中一对先合成；剩余一只保持原等级。具体先选哪一对可由 Tech 采用确定性规则，但不得出现复制、三合一、漏删或重复计分。
- 四个同级猫在物理条件允许时可以形成两次独立合成；若生成的两个高一级猫随后接触，可继续触发更高一级合成。

### 9.4 连续合成
- 新生成的猫从下一次合成结算步骤起可继续参与合成。
- 因一次投放造成的多次连续合成全部有效，且每次分别计分。
- MVP 不增加“连击倍率”“Combo 奖励”或额外掉落。
- 连续合成表现可以很快，但逻辑上必须保持每一级真实生成、每次消费和每次计分可追溯，禁止跨级直接跳过中间合成。

## 10. 计分规则

### 10.1 计分来源
MVP 本局分数只由成功合成产生：
- 投放：0 分。
- 普通碰撞：0 分。
- 存活时间：0 分。
- 连击额外倍率：无。

### 10.2 合成分值
按“生成的结果等级”计分：

| Merge | Result | Score |
|---|---|---:|
| L1 + L1 | L2 | 10 |
| L2 + L2 | L3 | 20 |
| L3 + L3 | L4 | 40 |
| L4 + L4 | L5 | 80 |
| L5 + L5 | L6 | 160 |
| L6 + L6 | L7 | 320 |
| L7 + L7 | L8 | 640 |
| L8 + L8 | L9 | 1280 |
| L9 + L9 | L10 | 2560 |

每次成功合成先确认两个源猫被有效消费，再把对应分值加到 `score`，避免重复触发造成重复加分。

本 PRD 负责输出最终本局 `score`；最佳分比较、显示和持久化在 Scoring / UX / Platform 后续任务中完成。

## 11. 危险线与失败判定

### 11.1 危险线位置基线
危险线初始基线位于“可玩棋盘高度自底向上约 82%”的位置，即顶部约 18% 区域属于危险区域。

最终像素位置需要结合顶部投放区、安全区和设备比例由 UI/Tech 对齐，但不得把危险线移动到导致 Current 在正常瞄准时被判定失败的位置。

### 11.2 越线条件
满足以下条件的猫参与危险检测：
- 已释放，是 Active Cat。
- 未被合成消费。
- 其有效碰撞体任意部分位于危险线之上。

Current 在释放前完全排除在危险检测之外。

### 11.3 连续容错
- 只要至少一个有效猫满足越线条件，Danger State 从 `SAFE` 进入 `WARNING`，Danger Timer 从 0 开始累计。
- 容错时间固定为 `2.0s`。
- 在 2.0s 到达前，如果所有有效猫都回到危险线以下（例如下落、滚动或合成释放空间），Danger State 立即回到 `SAFE`，Danger Timer 重置为 0。
- 下一次再次越线时重新从 0 开始，不累计之前的警告时间。
- WARNING 期间游戏继续运行：允许投放、物理移动和合成，玩家有机会“救场”。
- 暂停或进入后台时 Danger Timer 停止累计。

### 11.4 Game Over 顺序
每个逻辑更新周期中，失败判断顺序为：
1. 处理当前物理结果。
2. 处理本周期有效合成和对象消费。
3. 基于合成后的有效猫集合更新危险线条件。
4. 若 Danger Timer 达到 2.0s 且仍存在越线猫，则进入 `GAME_OVER`。

因此，在临界时刻发生并成功清除危险区域的合成应优先于失败结算，避免“已经合掉但仍被判死”。

进入 `GAME_OVER` 后：
- 禁止新的瞄准释放输入。
- 固定最终 `score`。
- 不再产生新的合成计分。
- 向后续结算流程输出：最终分数、达到过的最高等级、结束原因 `DANGER_TIMEOUT`。

## 12. 重开核心重置

用户从后续结算流程触发“重新开始”时，核心玩法必须视为全新一局：
- 清空所有 Active Cat 和待处理合成。
- `score = 0`。
- 最高等级记录（本局）重置。
- Danger State = `SAFE`，Danger Timer = 0。
- 重新随机生成 Current + Next。
- Spawn State = `AIMING`。
- Run State = `RUNNING`。

本地最佳分不得因核心重置被清除；其持久化属于后续任务。

## 13. 对外事件 / 数据语义

后续 Tech Design 可以采用不同代码命名，但必须能表达以下产品事件：
- Run started / restarted.
- Current aim position changed.
- Cat released.
- Spawn unlocked.
- Cat merge succeeded: source level, result level, score delta.
- Highest level changed.
- Danger warning started / cleared / timer progress.
- Game over: reason, final score, highest level.

本节只定义语义，不构成 API、类名或协议格式约束。

## 14. Acceptance Criteria

### AC-01 新局初始化
启动新局后，棋盘为空、分数为0、危险计时为0，Current 与 Next 均只能来自 L1–L3，且玩家可进入 AIMING。

### AC-02 随机投放池
连续大量生成时不得出现 L4–L10 的直接投放；L1/L2/L3 均具备约等概率出现机会，允许连续重复等级。

### AC-03 水平瞄准边界
玩家把瞄准位置移动到最左/最右时，释放瞬间 Current 的有效碰撞体仍完全位于侧墙内；释放后玩家无法再直接操控该猫。

### AC-04 投放节流
释放一只猫后，在其未离开投放排除带或 0.25s 最小锁定时间尚未结束时，第二只猫不能被再次释放；两条件满足后恢复 AIMING。

### AC-05 同级合成
L1–L9 任意同级两猫有效接触时，两源对象只被消费一次并生成一个高一级猫；异级接触不合成。

### AC-06 最高级
L9+L9 可生成 L10 并正常计分；L10+L10 只发生物理碰撞，不生成 L11，不产生新合成分。

### AC-07 三体同时接触
三个同级猫同时接触时不得出现三合一、复制、重复删除或重复计分；只允许一对先完成一次合法合成，第三只保持可追溯状态。

### AC-08 连续合成
一次投放导致多个合法合成时，每次升级都按顺序真实发生，每次对应源对象只消费一次，分数为所有成功合成分值之和，无额外Combo倍率。

### AC-09 分数
每次合成增加的分数严格符合第10.2节表格；投放、普通碰撞和存活时间都不能直接增加分数。

### AC-10 危险警告可恢复
任意 Active Cat 越线后进入 WARNING；在2秒前所有猫回到线下时，警告取消且计时归零，再次越线必须重新从0累计。

### AC-11 合成救场优先
在 Danger Timer 接近2秒时，如果本周期合法合成使所有有效猫回到危险线以下，本局不得结束，危险计时应清零。

### AC-12 Game Over
至少一只有效猫连续越线达到2.0秒后进入 GAME_OVER；此后不能再投放或继续增加合成分，并输出最终分数、最高等级和 `DANGER_TIMEOUT`。

### AC-13 暂停/后台公平性
当核心游戏被外部暂停或应用进入后台时，物理模拟与 Danger Timer 均停止推进；恢复后从暂停前状态继续，不因真实世界经过时间直接失败。

### AC-14 重开
重开后棋盘、分数、危险状态、本局最高等级和投放队列全部重新初始化，不继承上一局物理对象或待处理合成。

## 15. 下游依赖与专业任务

本 PRD 已于 2026-09-16 获得用户 `USER_APPROVED`，现可作为正式输入解锁：
- Art Direction：10级猫咪视觉分级、轮廓与尺寸可读性原则。
- Tech Design：物理模块、合成结算、防重复消费、配置结构和跨平台一致性方案。
- UI/UX：瞄准手势、Current/Next 信息、危险线与警告表现。
- Client：核心玩法实现。
- QA：可追溯到 AC-01 ~ AC-14 的测试设计。

## 16. 风险与调优点

- 猫咪尺寸增长如果过快，会使高等级出现后难度陡增；过慢则缺少成长感，需要原型验证。
- 物理弹性、摩擦、质量和形状会显著改变堆叠稳定性，但具体参数由 Tech 原型调优，不能反向改变本 PRD 的核心语义。
- 危险线82%高度与2秒容错共同决定失败压力；本版锁定2秒，危险线位置可在不改变产品意图的前提下于专业评审中提出变更，但变更需要 Product 记录并重新审批对应版本。
- 等概率 L1–L3 是MVP最透明的基线；若原型表明高等级生成速度过快/过慢，可由 Product 提交新版本调整权重。
- 可见美术轮廓与碰撞轮廓差异过大会造成公平性感知问题，必须在 Art / Tech 阶段联合评审。
